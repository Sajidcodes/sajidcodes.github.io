0. Foundations of Programming

What Is Programming?

Before learning Python, it is important to understand what programming actually is. In this section, you will learn how programs work, how programming languages communicate instructions, how Python executes code, and how programmers solve problems.

0.1 What Is Programming?

1. What Is a Computer Program?

A computer program is a set of instructions that tells a computer what to do.

A program receives information, processes that information, and produces a result.

Think of a program like a recipe.

  1. Get two eggs.
  2. Crack the eggs.
  3. Mix them.
  4. Cook them.

A computer program works in a similar way:

Information → Processing → Result

Programming languages provide rules and structures that allow humans to describe what a computer should do.

Some programming languages include:

  • Python
  • Java

  • JavaScript
  • C#
  • Go

Different languages have different syntax, features, and common uses.

3. Source Code vs. Machine Code

Source code

Source code is the human-readable code written by a programmer.

Machine code

Machine code consists of low-level instructions that a processor can execute.

Consider this simple Python program: 

x = 10
print(x)

This is source code. A human programmer can read it and understand roughly what it means.

But what does machine code look like?

At the processor level, instructions are represented as binary data. For example, a simplified sequence of machine bytes might look like: 

10110000 01100010

or when represented in hexadecimal: 

B0 62

Important: The machine-code bytes shown above are an illustrative example of what low-level processor instructions can look like. They are not the machine-code translation of the Python statement x = 10.

Why not?

Because Python, particularly CPython, uses another important layer: bytecode.

Python source code → Python bytecode → Python Virtual Machine → Machine instructions

Python source code

x = 10
print(x)

Python bytecode

CPython internally compiles Python source into bytecode. You may see instructions conceptually represented like: 

LOAD_CONST
STORE_NAME
LOAD_NAME
CALL
RETURN_VALUE

The exact bytecode depends on the Python version and implementation. You do not need to memorize these instructions.

The important idea

Level Example Who primarily works with it?
Source code print("Hello") Programmer
Bytecode Python VM instructions Python implementation
Machine code Binary/processor instructions CPU

You will be able to:

  • Explain what source code is.
  • Explain what machine code is.
  • Distinguish human-readable source code from low-level instructions.
  • Explain that Python commonly introduces a bytecode layer between source code and execution.

4. Interpreters vs. Compilers

Interpreter

An interpreter is a program that reads and executes instructions from a programming language.

Compiler

A compiler translates source code into another form, often machine code or an executable representation, before the resulting program is run.

A simplified interpreter model

Source Code → Interpreter → Execution

A simplified compiler model

Source Code → Compiler → Executable / Machine Code → Run

Example: Python

Suppose you create a file called hello.py: 

print("Hello")

You can run it using: 

python hello.py

The Python implementation processes the source code and executes it.

Example: C

A C program can be compiled before execution: 

C source code
      ↓
Compiler
      ↓
Executable program
      ↓
Run

Don't think of this as "Python has no compilation"

The interpreter-versus-compiler distinction is useful for beginners, but real language implementations can be more complicated.

CPython first compiles Python source code into bytecode and then the Python runtime executes that bytecode.

You will be able to:

  • Explain the basic idea of an interpreter.
  • Explain the basic idea of a compiler.
  • Describe the simplified difference between interpreting and compiling.
  • Understand that real programming-language implementations can combine these ideas.

5. What Happens When You Run Python?

Let's follow one small Python program from source code to output.

Output will appear here.

Step 1 — You write source code

x = 10

total = x + y

Step 2 — Python reads the program

Python processes the source code and determines whether the code can be understood according to Python's rules.

Step 3 — Python compiles the source

In CPython, the source is compiled into Python bytecode.

Source → Bytecode

Step 4 — Python executes the instructions

The Python runtime executes the resulting bytecode.

Step 5 — Values are created

When Python encounters: 

x = 10

the name x becomes associated with the value 10.

Then: 

y = 20

associates y with 20.

Step 6 — Python performs the calculation

total = x + y

Python obtains the values associated with x and y, adds them, and associates the resulting value 30 with total.

Step 7 — Python calls print()

print(total)

Python obtains the value of total and sends it to the program's output.

The result is: 
30

The complete simplified picture

You write Python → Python processes it → Bytecode → Python runtime executes it → Output

6. Algorithms and Instructions

An algorithm is a sequence of steps used to solve a problem.

Algorithms are not unique to programming. You use algorithms every day.

Example: Making Toast

  1. Get bread.
  2. Put bread in toaster.
  3. Start toaster.
  4. Wait.
  5. Remove toast.

Example: Finding the Largest Number

Suppose we have: 

5, 12, 7

A possible algorithm is:

  1. Start with 5 as the largest.
  2. Compare 12 with 5.
  3. 12 is larger, so make 12 the largest.
  4. Compare 7 with 12.
  5. 7 is not larger.
  6. The answer is 12.

Foundations: The Big Picture

You have now seen the basic ideas behind programming.

Problem → Algorithm → Source Code → Python → Execution → Output

When something goes wrong:

Bug → Debug → Fix → Test Again
Core idea:

Programming is not simply typing Python code. Programming is the process of solving problems by designing precise instructions that a computer can execute.
