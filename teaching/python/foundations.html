FOUNDATIONSGetting Started with Python

Before lists, loops, or functions — you need to know what a program actually is, how Python runs one, and the handful of building blocks every single line of code is made from. This module is the ground floor. Take it slow. Every example below has a ▶ Run button — click it and watch the real output appear, right in the page.

0.1 · What is a program?

A program is a list of instructions, written in a language a computer can follow, executed one line at a time, top to bottom — unless something tells it to skip around (that's what if-statements and loops do, later on). Python is a language for writing those instructions in something close to plain English.

★ Mental model

Think of a recipe. It doesn't matter how well you understand cooking — the oven only does exactly what the recipe says, in order, one step at a time. Python is the same: it has zero common sense and zero ability to guess what you meant. It just executes the literal instructions, line by line.

0.3 · Your first line: print()

print() displays something on the screen. It is how your program "talks" to you.

print("Hello, world!")

You can print multiple things at once, separated by commas — Python automatically puts a space between them:

print("The answer is", 42)
⚠ Common first mistake

Text must be wrapped in quotes — print(Hello) (no quotes) raises NameError, because Python thinks Hello is a variable name that doesn't exist yet. print("Hello") is correct. Try the broken version below and watch the real error:

print(Hello)

0.4 · Comments — notes the computer ignores

Anything after a # on a line is a comment. Python skips it completely — comments exist purely for humans reading the code.

# This whole line is ignored by Python
print("This runs")  # this part is ignored too
★ Mental model

Comments are sticky notes stuck to your code for future-you or a teammate. They explain why the code does something, not just what it does — the code itself already shows the "what."

0.5 · Variables — storing values with a name

A variable is a labeled box that holds a value. You create one with =, which means "store," not "equals" (that distinction becomes critical later in if-statements).

age = 21
name = "Sara"
is_student = True

print(name, "is", age)

Naming rules

  • Can contain letters, numbers, and underscores — but can't start with a number.
  • No spaces. Use underscores instead: my_variable, not my variable.
  • Case-sensitive: age and Age are two completely different variables.
  • Can't use Python's reserved words (if, for, class, return, etc.) as names.
⚠ Watch for…

Using a variable before you've assigned it raises NameError: name 'x' is not defined. Python doesn't guess — a name only exists after a line that creates it has actually run. Try it:

print(score)
score = 10

Reassigning a variable

score = 10
print(score)   # → 10
score = 25       # overwrites the old value completely
print(score)   # → 25

0.6 · The four basic data types

Every value has a type, and the type controls what you can do with it.

print(type(7))
print(type(7.0))
print(type("7"))

★ Mental model — the quotation-mark switch

Quotes turn anything into text. 7 is a number you can do math with. "7" is a string that just happens to look like a number — Python treats it completely differently, the same way "the word cat" isn't an actual cat.

0.7 · Getting input from the user

input() pauses the program, waits for the user to type something and hit Enter, then hands back whatever they typed — always as a string, even if they typed a number.

name = input("What's your name? ")
print("Hello,", name)
⚠ A note on this page

input() needs a real terminal to pause and wait for typing, so it won't work in the in-browser Run button here — that's why the block above doesn't have one. It works perfectly in IDLE, VS Code, or a terminal. Below, we simulate what input() hands back, using a hardcoded string instead, so you can still see the type problem in action.

# Simulating: age = input("Age: ")  →  user types 25
age = "25"       # input() always returns a string, even for numbers
print(age + 1)   # TypeError! Can't add int to str.

Fix it by converting with int() or float():

# Simulating: age = int(input("Age: "))
age = int("25")   # now age is a real int
print(age + 1)      # works!

→ Where % shows up constantly

n % 2 == 0 is the classic way to check if n is even — the remainder after dividing by 2 is 0 only for even numbers. You'll see this pattern everywhere once you hit loops and if-statements.

Order of operations

Python follows standard math order (PEMDAS): parentheses first, then exponents, then * / // % left to right, then + - left to right.

print(2 + 3 * 4)       # → 14   (multiplication happens first)
print((2 + 3) * 4)     # → 20   (parentheses force addition first)

0.10 · Comparison operators (a preview)

These compare two values and always produce a bool — you'll use these constantly starting with if-statements in the next module.

OperatorMeansExampleResult
==equal to5 == 5True
!=not equal to5 != 3True
< >less / greater than3 < 5True
<= >=less/greater or equal5 >= 5True
print(5 == 5)
print(5 != 3)
print(3 < 5)
print(5 >= 5)
⚠ Don't confuse these two

= stores a value into a variable. == asks "are these equal?" and gives back True or False. Mixing them up is the single most common beginner typo — and outside of an if-statement, x == 5 on its own line just computes a throwaway True/False and does nothing visible.

0.11 · Indentation — Python's grammar

You haven't written an indented block yet (that starts with if-statements and loops next module), but know this now: Python uses indentation — consistent spacing at the start of a line — instead of curly braces to show which lines belong together. Mixing tabs and spaces, or indenting inconsistently, causes an IndentationError. Most editors handle this for you automatically once you press Enter after a colon.

0.12 · Two error categories to recognize on sight

Error typeWhen it happensExample
SyntaxErrorThe code isn't valid Python grammar — caught before anything runsmissing a colon, mismatched parentheses
Runtime error
(NameError, TypeError, ValueError, etc.)		The grammar is fine, but something goes wrong while runningusing an undefined variable, adding a string to a number
✓ Read the last line of an error first

Python error messages look intimidating but the actual reason is almost always the very last line — e.g. NameError: name 'x' is not defined. Read that line first, then work upward if you need more context. Try breaking the code below on purpose:

print("Line 1 runs fine")
print(undefined_variable)
print("This line never runs")

Instant Quiz · Foundations

1. What does print("Age:", 21) output?
Age: 21 — Python inserts a space between comma-separated items.
2. What is type(4.0)?
float. The decimal point makes it a float even though the value is whole.
3. What does 10 % 3 evaluate to?
1. 10 divided by 3 is 3 remainder 1 — modulo gives just the remainder.
4. What does 10 // 3 evaluate to?
3. Floor division drops the remainder entirely and keeps only the whole number part.
5. What happens when you run print(Hello) without quotes?
NameError. Without quotes, Python looks for a variable named Hello, which doesn't exist.
6. What does int("7") + int("3") return?
10 — both strings are converted to real integers first, then added as numbers.
7. Why does "7" + "3" return "73" instead of 10?
Both are strings, so + glues (concatenates) them together as text rather than adding them as numbers.
8. Is 5 = x valid Python?
No — SyntaxError. The left side of = must be a variable name, not a value. You'd write x = 5 instead.
