Python Programming

0. Foundations of Programming

Before writing significant Python programs, learn what programming is, how programs are developed, and how programmers solve problems.

0.1 What Is Programming?

1. What Is a Computer Program?

Beginner idea: A computer program is a set of instructions that tells a computer what to do.

Think of a program like a recipe.

  1. Get two eggs.
  2. Crack the eggs.
  3. Mix them.
  4. Cook them.

A computer program does something similar:

  1. Get some information.
  2. Process the information.
  3. Produce a result.

Example — Calculator

Get 10 Get 5 Add them Display 15

Example — Login System

Ask for username Ask for password Check the information If correct → allow access If incorrect → show an error
Students should be able to:
  • Define a computer program.
  • Explain why computers need instructions.
  • Identify programs they use every day.

2. Programming Languages

Beginner idea: A programming language is a language humans use to give instructions to computers.

Programmers use languages such as:

  • Python
  • Java
  • C++
  • JavaScript
  • C#
  • Go

Different programming languages have different rules and purposes.

Python

print("Hello, world!")

This tells Python to display:

Hello, world!

JavaScript

console.log("Hello, world!");

Both programs accomplish a similar task, but they use different programming languages.

Students should be able to:
  • Define a programming language.
  • Name several programming languages.
  • Recognize Python as a programming language.

3. Source Code vs. Machine Code

Beginner idea: Source code is the code programmers write. Machine code is low-level code that the processor can execute.
Human ↓ Python source code ↓ Python interpreter ↓ Machine-level instructions ↓ Computer

Example

x = 10
print(x)

This is source code. Python processes it into instructions that can ultimately be executed by the computer.

Another example

2 + 3

You understand this as “add 2 and 3.” At the lowest level, the processor works with machine instructions represented as binary data.

Key idea: Source code is written by programmers, while machine code consists of instructions the computer's processor can execute.

4. Interpreters vs. Compilers

Beginner idea: Both interpreters and compilers help translate programming languages into something the computer can execute.
Interpreter: Code → Process / execute Compiler: Code → Translate → Executable / program → Run

Python is commonly described as an interpreted language because Python programs are executed through the Python interpreter.

Python

print("Hello")

You can run the file with:

python hello.py

The Python interpreter processes the program.

Compiled language

C source code ↓ Compiler ↓ Machine / executable code ↓ Run program
Keep it simple for now: Focus on the basic difference between interpreting and compiling. Do not memorize complicated implementation details yet.
Students should be able to:
  • Explain the basic difference between an interpreter and a compiler.
  • Identify the Python interpreter as the program that executes Python code.

5. What Happens When You Run Python?

When you run:

print("Hello")

the simplified process is:

You write Python code ↓ Python interpreter reads the code ↓ Python checks the code ↓ Python executes the instructions ↓ Computer displays: Hello

Example

x = 10
y = 20
print(x + y)

The program:

  1. Creates x.
  2. Stores 10.
  3. Creates y.
  4. Stores 20.
  5. Adds them.
  6. Displays 30.

Another example

name = "Sajid"
print("Hello", name)

Output:

Hello Sajid
Students should be able to: Describe what generally happens when a Python program runs.

6. Algorithms and Instructions

An algorithm is a sequence of steps used to solve a problem.

You already use algorithms in everyday life.

Example — Making Toast

  1. Get bread.
  2. Put bread in toaster.
  3. Start toaster.
  4. Wait.
  5. Remove toast.

Example — Finding the Largest Number

Suppose we have:

5, 12, 7
  1. Start with 5 as the largest.
  2. Compare 12 with 5.
  3. 12 is larger → largest = 12.
  4. Compare 7 with 12.
  5. 7 is not larger.
  6. Answer = 12.
Students should be able to:
  • Explain what an algorithm is.
  • Create simple step-by-step instructions.
  • Apply an algorithm to a simple problem.

7. Syntax vs. Logic

This distinction is very important for beginners.

Syntax

Syntax means the rules for writing code correctly.

Correct:

print("Hello")

Incorrect:

print("Hello"

The closing ) is missing.

Logic

Logic is whether your program does the correct thing.

age = 20

if age > 21:
    print("Allowed")

The code may be syntactically correct. But if the intended rule is “21 or older,” the logic is wrong.

Correct:

if age >= 21:
    print("Allowed")

Logic example

price = 100
discount = 10
final_price = price + discount

The code may run, but the logic is wrong if the discount should be subtracted.

Correct:

final_price = price - discount
Remember: Syntax = Is the code written correctly?
Logic = Does the code do what we intended?

8. Bugs and Debugging

A bug is a problem or error in a program. Debugging is the process of finding and fixing bugs.
Program doesn't work ↓ Find the problem ↓ Understand the problem ↓ Fix the problem ↓ Test again

Syntax bug

print("Hello"

Fix:

print("Hello")

Logic bug

number = 10

if number > 10:
    print("Number is 10 or greater")

Nothing prints because 10 is not greater than 10.

If the intended rule includes 10, fix it:

if number >= 10:
    print("Number is 10 or greater")
Students should be able to:
  • Identify a bug.
  • Explain why it happened.
  • Modify code to fix it.
  • Test the program again.

0.2 The Software Development Process

Programming isn't simply:

Open Python → Start typing

Professional programming follows a process.

Problem ↓ Requirements ↓ Algorithm ↓ Pseudocode / Flowchart ↓ Implementation ↓ Testing ↓ Debugging ↓ Documentation ↓ Maintenance

1. Problem Definition

First, determine what problem you are trying to solve.

Don't immediately write code.

Example — Grade Calculator

Students need a program that calculates their final grade.

Example — Temperature Converter

Users need a program that converts Fahrenheit temperatures to Celsius.
Students should be able to: State the problem clearly before programming.

2. Requirements

Requirements describe what the program needs to do.

Grade calculator

Input
  • Homework grade
  • Exam grade
Process
  • Calculate average
Output
  • Final grade

Shopping program

Input
  • Product price
  • Quantity
Output
  • Total cost

Login program

Input
  • Username
  • Password
Output
  • Login successful
  • OR Login failed
Students should be able to: Identify the inputs and outputs required by a problem.

3. Algorithm Design

Now determine the steps needed to solve the problem.

Example — Area of Rectangle

  1. Get length.
  2. Get width.
  3. Multiply length × width.
  4. Display area.

Example — Even or Odd

  1. Get a number.
  2. Divide the number by 2.
  3. Check the remainder.
  4. If remainder is 0 → even.
  5. Otherwise → odd.
Students should be able to: Create an algorithm for a simple problem.

4. Pseudocode

Pseudocode describes a program using simple human language before writing actual code.

Example — Calculate Area

START
GET length
GET width
SET area = length × width
DISPLAY area
END

Example — Check Age

START
GET age

IF age >= 18
    DISPLAY "Adult"
ELSE
    DISPLAY "Minor"

END
Students should be able to: Convert a problem into simple pseudocode.

5. Flowcharts

A flowchart is a visual representation of an algorithm.

Common symbols:

  • Oval → Start / End
  • Rectangle → Process
  • Diamond → Decision
  • Arrow → Direction

Example — Even/Odd

Start ↓ Get number ↓ Is number divisible by 2? ↙ ↘ Yes No ↓ ↓ Even Odd ↘ ↙ End

Example — Login

Start ↓ Enter password ↓ Password correct? ↙ ↘ Yes No ↓ ↓ Login Error successful ↓ End
Students should be able to: Read a flowchart and create a simple flowchart from an algorithm.

6. Implementation

Implementation means turning your algorithm into actual code.

Example — Rectangle Area

Pseudocode:

GET length
GET width
CALCULATE area
DISPLAY area

Python:

length = 10
width = 5
area = length * width
print(area)

Output:

50

Example — Greeting

name = "Maria"
print("Hello", name)
Students should be able to: Translate simple algorithms into Python code.

7. Testing

Testing means checking whether the program works correctly.

Don't test only one example.

Example — Addition

def add(a, b):
    return a + b

Test cases:

  • 2 + 3 = 5
  • 10 + 20 = 30
  • 0 + 5 = 5

Example — Age Checker

  • 25 → Adult
  • 18 → Adult
  • 17 → Minor
  • 0 → Minor
Students should be able to: Create test cases and determine whether the output is correct.

8. Debugging

Testing may reveal a problem. Debugging is finding and fixing that problem.

Example

You expect:

20

but your program produces:

15

You investigate the calculation and find the error.

Another example

Your program crashes when the user enters:

abc

instead of a number. You investigate why the program cannot handle that input.

Students should be able to:
  1. Observe the problem.
  2. Locate the likely cause.
  3. Fix the code.
  4. Test again.

9. Documentation

Documentation explains how a program works and how other people should use or maintain it.

Documentation can include:

  • Comments
  • Function descriptions
  • Instructions
  • README files
  • Examples

Example — Comment

# Calculate the total price
total = price * quantity

Example — Program instructions

How to use the program:
  1. Enter your name.
  2. Enter your age.
  3. Press Enter.
  4. The program displays your category.
Students should be able to: Add useful documentation to their programs.

10. Maintenance

A program doesn't necessarily end when you finish writing it.

Maintenance means modifying and improving software after it has been created.

Example — Grade Calculator

You created a grade calculator. Later, the school changes the grading system. You update the program.

Example — Calculator

A calculator originally supports:

  • Addition
  • Subtraction

Later, users request:

  • Multiplication
  • Division

You modify the program to support the new features.

Students should understand: Software changes over time and often needs updates, fixes, and improvements.
