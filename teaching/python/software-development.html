0.2 The Software Development Process

From Problem to Working Software

Programming is not simply opening Python and starting to type. Programmers use a process to understand a problem, design a solution, write the code, test it, fix problems, document it, and improve it over time.

The Big Picture

Problem → Requirements → Algorithm → Pseudocode / Flowchart → Implementation → Testing → Debugging → Documentation → Maintenance

1. Problem Definition

Problem definition means clearly identifying the problem that the program needs to solve.

Before writing code, first ask:

What problem are we trying to solve?

Example: Grade Calculator

Problem:

Students need a program that calculates their final grade.

Example: Temperature Converter

Problem:

Users need a program that converts Fahrenheit temperatures to Celsius.

Example: Shopping Calculator

Problem:

A customer needs a program that calculates the total cost of products.

The important step is to describe the problem clearly before deciding how to implement it.

2. Requirements

Requirements describe what the program needs to do.

Example: Grade Calculator

Input:
    Homework grade
    Exam grade

Process:
    Calculate the average

Output:
    Final grade

Example: Shopping Program

Input:
    Product price
    Quantity

Process:
    price × quantity

Output:
    Total cost

Example: Temperature Converter

Input:
    Fahrenheit temperature

Process:
    Convert Fahrenheit to Celsius

Output:
    Celsius temperature
Key question:

What information does the program receive, what does it do with that information, and what result should it produce?

3. Algorithm Design

An algorithm is a sequence of steps used to solve a problem.

Example: Rectangle Area

  1. Get the length.
  2. Get the width.
  3. Multiply length × width.
  4. Display the area.

Example: Even or Odd

  1. Get a number.
  2. Divide the number by 2.
  3. Check the remainder.
  4. If the remainder is 0, the number is even.
  5. Otherwise, the number is odd.

Why design the algorithm first?

Writing the steps before writing Python forces you to think about the solution rather than immediately thinking about syntax.

4. Pseudocode

Pseudocode describes a program using simple human language without requiring exact programming-language syntax.

Example: Calculate Area

START

GET length

GET width

SET area = length × width

DISPLAY area

END

Example: Check Age

START

GET age

IF age >= 18

    DISPLAY "Adult"

ELSE

    DISPLAY "Minor"

END

Notice that pseudocode looks somewhat like programming, but it does not need to follow Python's exact syntax.

5. Flowcharts

A flowchart is a visual representation of an algorithm.

Common symbols

Oval       → Start / End

Rectangle  → Process

Diamond    → Decision

Arrow      → Direction

Example: Even or Odd

Start ↓ Get number ↓ Is it divisible by 2? ↓ Yes → Even / No → Odd ↓ End

The goal is not to memorize drawing conventions. The goal is to understand how an algorithm can be represented visually.

6. Implementation

Implementation means turning an algorithm into actual program code.

Example: Rectangle Area

Algorithm:

GET length
GET width
CALCULATE area
DISPLAY area

Python implementation:

length = 10
width = 5

area = length * width

print(area)

Output:

50

Another example: Greeting

Algorithm:

GET name
DISPLAY greeting

Python:

name = "Maria"

print("Hello", name)

Output:

Hello Maria

7. Testing

Testing means checking whether a program works correctly.

A program should not be tested with only one example.

Example: Addition

def add(a, b):
    return a + b

Possible test cases: 

2 + 3 = 5

10 + 20 = 30

0 + 5 = 5

-2 + 5 = 3

Example: Age Checker

18 → Adult

25 → Adult

17 → Minor

0 → Minor

Different inputs help us discover problems that a single test might not reveal.

8. Debugging

Debugging means finding and fixing problems in a program.

Suppose a program should produce: 

20

but instead produces: 

15

The programmer needs to investigate:

  1. What was expected?
  2. What actually happened?
  3. Where did the difference occur?
  4. What caused it?
  5. How can it be fixed?
  6. Does the corrected program work?
Observe → Locate → Understand → Fix → Test

9. Documentation

Documentation explains how a program works and how people should use or maintain it.

Documentation can include:

  • Comments
  • Function descriptions
  • Instructions
  • README files
  • Examples

Example: Comment

# Calculate the total price

total = price * quantity

Example: User Instructions

How to use the program:

1. Enter your name.
2. Enter your age.
3. Press Enter.
4. Read the result.

Good documentation helps another person understand your program without having to reverse-engineer every line of code.

10. Maintenance

Maintenance means modifying, improving, and updating software after it has been created.

Example: Grade Calculator

Suppose a school changes its grading system. The existing program needs to be updated.

Example: Calculator

A calculator originally supports: 

Addition
Subtraction

Later, users request: 

Multiplication
Division

The software is modified to support the new requirements.

Important idea:

Software is rarely "finished forever." Requirements change, users discover problems, new features are requested, and environments change.

Foundation: How Programmers Think

The most important idea in this section is that programming begins with problem solving, not syntax.

Understand the Problem → Design a Solution → Write the Code → Test → Debug → Improve
You will be able to:
  • Describe the major stages of software development.
  • Define a programming problem before writing code.
  • Identify program inputs, processes, and outputs.
  • Create simple algorithms.
  • Write basic pseudocode.
  • Read simple flowcharts.
  • Translate algorithms into Python.
  • Create basic test cases.
  • Debug simple programs.
  • Explain why documentation and maintenance matter.
