Experiment Log

Baseline, changes and results in one place. Every number is a 3-run mean on the same 30 tasks.

EVALUATION BASELINE EXPERIMENTS RESULTS 2026-10-19
If you read one thing
  • A from-scratch terminal agent scores 84.4% ± 1.9% on a 30-task suite I built and validated (oracle 30/30, negative controls 0/30).
  • Retries improved recovery but not the pass rate. Routing cut cost by 64% and dropped the pass rate to 63.3%.
  • The safety validator went from 60% to 98% catch rate with 0 false positives on its test set. That's a dev-set number, and I say so.

Method

  • Same 30 tasks, same code version (6e8df3a9), 3 runs per configuration.
  • Change one thing at a time against the baseline.
  • Report the mean and sample standard deviation, overall and per tier.
  • Judge each change on tier 3 (debugging), where the agent loses most of its points, without letting tier 1 drop.

Entry 1: Retries

Change: after a failed command, add a hint to the tool result; allow 2 retries. Result: +2.3 points, about one standard deviation. Recovery up, failed commands down (117 → 98). Verdict: no proven gain. Details in section 08.

Entry 2: Model Routing

Change: gpt-4o for step 0 and after failures, gpt-4o-mini otherwise (70% of calls). Result: −64% cost, −21 points, −30 on debugging. Verdict: too costly in quality as designed. Details in section 12.

What I Take From This

  • A plausible feature isn't an improvement until it beats the noise.
  • Cost savings need a quality number next to them.
  • Per-tier results showed where each change hurt. The overall average hid that.
Scope of these numbers

The agent numbers on this page come from my own 30-task suite. A suite I wrote can be easier to do well on than one I didn't, so I don't compare them with public Terminal-Bench scores.
