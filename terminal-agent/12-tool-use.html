Tool Use

One tool, a shell command, with limits around it that the model can't remove.

AGENTS TOOL CALLING SAFETY BUILD LOG 2026-10-19
In short
  • The agent has exactly one tool: run_command.
  • Every command passes a safety validator first, and runs with no secrets in its environment.
  • I chose limits in the harness over instructions in the prompt, because the model can ignore a prompt.

Why One Tool

A shell already covers reading files, editing them, running tests and using git. Separate tools like read_file or write_file would be more surface for the model to misuse and more code for me to debug, for no new capability.

Decision

Start with one general tool. Add a specialised tool only if traces show a repeated failure that it fixes.

ta/bin/python -m agent "your instruction" --workdir DIR [--model M] [--max-steps N]

The default model is gpt-4o. The default step limit is 25.

Limits on Each Command

  • No secrets. The command runs with a clean environment: no API keys, no tokens. If the agent can't see a key, it can't leak one.
  • HOME is the workspace. Writes to ~ stay inside the task folder.
  • Validator first. A rule-based validator reads each command before it runs and can block it. Refer to section 25.
  • In Harbor: 60 s timeout per command. Output over 8000 characters is cut, to protect the context window.
Decision: layers, not one wall

The validator is one layer. The clean environment is another. On Terminal-Bench, the Docker container is the outer layer. No single layer has to be perfect.

What Gets Recorded

Every tool call goes into the JSONL trace: command, exit code, output, duration and the validator's decision. Refer to section 21, Observability.
