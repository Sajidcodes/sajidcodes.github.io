Cost

Cost is a metric like pass rate: measured per call, reported per task, and capped in code.

COST BUDGET ROUTING BUILD LOG 2026-10-19
In short
  • Baseline: about $0.016 per task with gpt-4o. A full 3-run experiment costs about $1.40.
  • Routing to gpt-4o-mini cuts that to $0.006, but costs 21 points of pass rate.
  • A hard budget cap stops the agent before a call, not after the bill.

How Cost Is Measured

Every model call is priced from its real token counts, using a price table per model (per 1M tokens):

ModelInputOutput
gpt-4o$2.50$10.00
gpt-4o-mini$0.15$0.60

The baseline used about 440k input tokens and 30k output tokens over 90 task runs. Input is over 90% of the tokens: the agent re-reads its whole history at every step. Most of the cost is context, not answers.

Why I report them together

"−64% cost" sounds like a clean win until you see the pass rate next to it. Per solved task, the cost goes from $0.0185 to $0.0088: a 52% saving, not 64%. And the tasks it gives up are the hard ones.

The Budget Cap

Benchmark tasks are long and run in parallel. A loop that gets stuck can keep calling the model. So the limit lives in code:

  1. Set TA_BUDGET_USD to a dollar limit.
  2. After each model call, its cost is added to a shared JSON ledger, under a file lock.
  3. Before each call, the agent reads the ledger.
  4. At or over the limit, the agent stops with the reason budget.
Decision: unknown models are charged at the highest known price

If I forget to add a model to the price table, the cap fails safe. It stops too early, never too late.

Trade-off

The check runs before each call, so parallel trials can go over the limit by about one call each. A lock around the whole call would prevent this, but it would also make the trials run one at a time.
